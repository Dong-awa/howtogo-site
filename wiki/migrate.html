迁移地图数据

问道把「在哪个世界画了什么」记在 config/howtogo/ 下，而目录名是由世界名或服务器地址 算出来的，不是你随手起的名字。所以一改世界名、一换服务器地址、一搬游戏实例， 数据不会自己跟过去——它没有丢，只是模组按新名字去找，没找到。 这一页讲目录名怎么算、哪些操作其实不用搬、要搬的时候按什么顺序做； 「改名之后路没了」的常见情况都能在这里找回。这里说的是问道自己的数据—— 路网、地点与公共交通线路；Xaero 世界地图自己的缓存不在 config/howtogo/ 里， 也不该在这里搬。

一句话：名字决定目录。要搬数据，先让新名字把目录建出来，再把旧目录里的 .json 复制进去——.world 标记留给游戏自己写。

数据在哪，目录名怎么来的

所有数据都在你这个游戏实例的 config/howtogo/ 下。官方启动器就是 .minecraft/config/howtogo/；用 PCL、HMCL 这类启动器时，是那个实例的「游戏目录」下的 config（开了版本隔离则在对应版本目录里），不是启动器自己的安装目录。 别去存档的 saves 目录里找：联机时客户端读不到服务器存档，所以问道从一开始就把数据放在 config 里，而不是存档旁边。

config/howtogo/ 下再按世界分目录。世界的标识由两样东西算出来： 单人存档用世界名（level.dat 里的 LevelName，就是选存档界面里 显示的那个名字），多人服务器用服务器地址（你填进服务器列表的那一串，不是它上面的显示名）。 算出来的 key 前面再加上 sp_ 或 mp_：

你在游戏里看到的 世界名（key） config/howtogo/ 下的目录
单人存档，世界名「江南」 sp_江南 sp___
单人存档，世界名「My World」 sp_My World sp_My_World
服务器地址填 mc.example.net mp_mc.example.net mp_mc.example.net
服务器地址填 mc.example.net:25565 mp_mc.example.net:25565 mp_mc.example.net_25565

算目录名时只保留 A-Z、a-z、0-9、.、 _、-，其余每个字符各换成一个下划线。 所以空格、冒号、中文都会变成下划线：中文世界名有几个字，目录名里就有几个下划线。 注意这是「按字符替换」，不是「换成拼音」，也不是「截断」。

每个世界目录里再按维度分文件。维度名同样按上面的规则清洗， : 变成下划线，所以 minecraft:overworld 会变成 minecraft_overworld：

维度 id 文件名前缀
minecraft:overworld（主世界） minecraft_overworld
minecraft:the_nether（下界） minecraft_the_nether
minecraft:the_end（末地） minecraft_the_end
模组维度，例如 mymod:sky mymod_sky
文件 内容
<维度>.json 道路网络：节点、路段、道路名称、地点与地点类型。
<维度>-lines.json 公共交通线路：线路名、类型、按顺序的站点。
<维度>-rail-names.json 自动识别铁路的名称（按路段两端坐标记，所以能跟着铁路图层重建）。

每个世界目录里还有一个没有扩展名的 .world 文件，内容是「这个目录属于哪个世界」。 它只为一件事存在：中文世界名清洗后都变成下划线，两个字数相同的不同中文名就会 撞成同一个目录名（例如「江南」和「江北」都是 sp___）。有了它，第二个世界会改用 sp___-<短哈希>，不会读到别人的路。这是 0.2.1 起才有的规则； 以前留下的目录没有这个文件，会由第一个打开它的世界认领，所以升级后老路径还能原地继续用。

config/howtogo/ 根目录下还有几个与存档无关的文件： route_preferences.json（上次选的出行偏好与语音开关）、 map_filter.json（地图显示面板的开关与位置）、 mtr_line_marks.json（MTR 线路的逐条轨道标记）。它们不属于任何一个世界， 搬单个世界时不用动；完整清单见 配置与数据文件。

哪些操作要搬，哪些不用

先分清一件事：问道认的是世界名，不是存档文件夹名。 世界名存在 level.dat 里，改文件夹不会改它。

操作 数据会怎样 要做什么
在 saves/ 里把存档文件夹改名（level.dat 不动） 世界名没变，目录也没变，照常读到 什么都不用做
改世界的显示名（level.dat 里的 LevelName；有些工具的重命名会连它一起改） 目录跟着新名字走 按下面「搬运步骤」搬
在服务器列表里改「服务器名称」 只是显示名，地址没变 不用搬
改服务器地址、域名、端口，或从 IP 换成域名 目录从 mp_旧地址 换成 mp_新地址 按下面「搬运步骤」搬
换电脑、换整合包、换游戏实例 数据还在旧实例的 config 里 复制整个 config/howtogo/
复制存档做备份，然后打开了副本 两个世界名相同，共用同一份数据 想让副本独立就先改名再搬
更新模组、删掉模组 jar 文件原样保留 不用搬

两个世界名一字不差时，问道分不开它们，会共用同一个目录——这是它唯一 不打算区分的撞车。名字不同但清洗后相同（典型是中文名）由 .world 处理，不需要你动手。所以「两个不同的存档共用了路」只可能是同名， 或者你还在用没有 .world 标记的旧版本。

搬运步骤：备份 → 先建新目录 → 只复制 JSON

下面这套顺序适用于所有情况，不要反过来做：

  1. 备份。把整个 config/howtogo/ 复制一份到桌面或别的盘。 这里没有校验和、也没有自动备份，复制是唯一的后悔药。
  2. 完全退出游戏。修改会在停手约 3 秒后自动写盘，离开世界时还会再存一次； 游戏开着时替换文件，退出时可能被内存里的旧路网写回去。
  3. 用新名字进一次目标世界（或目标服务器）。这一步会让问道按新名字建好目录、 写好 .world。地图上会空无一物，这是正常的——它现在找的是新目录。
  4. 再退出游戏，打开 config/howtogo/。旧目录还在，新目录已经出现。
  5. 把旧目录里的 .json 复制到新目录。包括 <维度>.json、<维度>-lines.json、 <维度>-rail-names.json。不要复制 .world， 也不要动根目录那几个文件。
  6. 进游戏验证。地图上应该有路、地点与线路；可选 /howtogo webmap 再 /howtogo webmap status，状态行里的 sp_... / mp_... 就是现在认的世界；/howtogo selftest 的「世界数据」一项也会把路网读一遍。

只有同一维度的文件会互相覆盖：旧世界的主世界文件对上新世界的 minecraft_overworld.json，下界、末地同理；旧世界没有的维度不用管， 新目录里也就不会有那个文件。

场景一：世界改名

单人存档的目录由 sp_<世界名> 算出来。再强调一次：世界名是 level.dat 里的名字，不是 saves/ 下的文件夹名。 只改文件夹不用搬；改了世界名才需要。

  • 新名字是英文时，目录通常就是 sp_NewName。
  • 新名字是中文时，清洗后的目录名可能和旧的一模一样（都是下划线）。这时问道会给新世界一个 sp___-<短哈希> 目录，把数据搬到那个目录里。
  • 操作就是上一节的六步：进一次新世界 → 退出 → 把旧目录的 JSON 复制进新目录。
  • 反悔很容易：旧目录没有被删，把 JSON 复制回去、或者把世界名改回去即可。

场景二：服务器地址变了

多人目录是 mp_<服务器地址>，取的是你在「服务器地址」框里填的那串字符： 域名、IP、端口都算，大小写也算；: 会被换成下划线。例如填 mc.example.net:25565，目录是 mp_mc.example.net_25565。 服务器列表里那个「服务器名称」不参与目录名，改它没有影响。

换地址（换域名、换端口、从 IP 换成域名、合租服换了入口）时，按通用步骤做： 用新地址进一次服务器让 mp_新地址 出现，退出，把 mp_旧地址 里的 JSON 复制进去。反过来也一样：把地址改回旧的那串，旧目录立刻又能读到。

如果两个地址下都已经有路（你在两个地址都玩过），问道没有合并功能： 同一维度只有一个 JSON，后复制的覆盖先复制的。先各自备份，再决定以哪份为准， 缺的那部分只能补画。

场景三：换电脑、换整合包、给朋友

数据是客户端本地的，不跟着存档走，也不跟着服务器走。换电脑、换整合包、 换游戏实例时，把整个 config/howtogo/ 复制到新实例的同一位置即可： 目录名、.world 都照原样过去，游戏目录的绝对路径变了也没关系—— 问道只认 config 下的相对结构。

只搬一个世界，也可以只复制对应的 sp_... / mp_... 目录： 世界名没变、.world 也对得上，放进去就能读。如果目标实例里已经有同名世界目录， 就按「搬运步骤」只复制 .json，别覆盖它的 .world。

想把客户端设置也带走，再加上 config/howtogo-client.toml。 route_preferences.json、map_filter.json、mtr_line_marks.json 都在 config/howtogo/ 里，会跟着整个目录一起走。

给朋友同理：打包 config/howtogo/ 发过去，解压到他游戏目录的 config/ 下。 最好两边用同一个模组版本；跨大版本搬之前先备份。真的读不回来时（例如文件被改坏）， 道路文件会被改名为 .corrupt 放到一边，不会静默消失。

场景四：复制存档以后，两个世界共用一份路

把存档文件夹复制一份，两个世界的 LevelName 通常还是同一个， 所以问道看它们是同一个世界，读写同一个数据目录。在副本里画的路，原世界也看得见； 反过来也一样。这不是 bug，是「按世界名区分」这条规则直接推出来的结果。

想让副本拥有独立的数据，可以这样拆开：

  1. 退出游戏，先备份当前共用的那个数据目录。
  2. 给副本改一个世界名（改 level.dat 里的 LevelName；只改文件夹名没有用）， 让两个世界的 key 不同。
  3. 打开改名后的副本一次，让它建立自己的新目录，然后退出。
  4. 把原目录里的 JSON 复制到副本的新目录。此后的修改就各记各的了。

手工改目录名，与 .world 的坑

先记住一条：目录名不是自由命名的。它必须正好等于按世界 key 算出来的那个名字。 如果只是为了让文件夹好看、随手把 sp_... 改成别的名字，问道下次会按原来的名字 新建一个空目录，改名后的那一份就没人读了——数据还在，但看起来「没了」。

知道规则以后，直接改目录名当然也能成，但要注意 .world： 它里面写的是原始世界 key（sp_ / mp_ 开头的那一整串， 例如 sp_My New World，空格和中文原样保留，不是目录名里的下划线）。 把一个带 .world 的目录改名成新名字后，内容还是旧世界名， 问道会认为这个目录不属于当前世界，于是另建一个 <新名字>-<短哈希> 目录—— 看起来就是「改了文件夹名，数据反而没了」。所以稳妥的做法是这几条：

  • 推荐：按「搬运步骤」来，让游戏自己建目录、自己写 .world， 你只复制 .json。
  • 或者：改完目录名后，删掉里面的 .world（下次打开世界时它会被重新写）。 前提是你接下来打开的就是目标世界；如果还有别的世界清洗后同名，先打开的那个会认领它。 旧版本留下的目录本来就没有 .world，改名到正确名字后直接就能被认领，不用做别的。
  • 也可以：用文本编辑器把 .world 的内容改成新的世界 key （sp_ 或 mp_ 开头的那一整串，不是目录名）。 这要求一字不差：sp_ / mp_、空格、大小写、端口里的冒号都要对上， 并用不带 BOM 的 UTF-8 保存，否则等于没改。

目录名后面带一段 -1a2b3c4d 这样的短哈希，不是坏了，是「这个名字已经被另一个世界认领了」。 短哈希由世界名算出来，同一个名字每次算出的后缀都一样，所以它不会天天变。 想知道哪个目录是游戏正在用的，看每个目录里的 .world：内容等于当前世界 key 的那一个才是。 用不到的哈希目录可以备份后删掉，但别在没确认之前删。

出错了怎么找回

改名后进游戏，路全没了——数据丢了吗？

通常没丢。新目录是空的，旧目录还完整地待在旁边。退出游戏，按「搬运步骤」把旧目录里的 .json 复制进新目录即可。注意先别在新世界继续画：复制旧文件会覆盖同名的道路文件， 如果已经画了新路，先把新文件备份出来再决定留哪份。

为什么多了一个 sp___-1a2b3c4d 这样的目录？

世界名清洗后撞车了：另一个世界已经占着不带哈希的那个目录名。 看两个目录里的 .world，把「属于当前世界」的那一个作为目标，数据搬进去。 旧的那份先留着，确认不需要再删。

我把整个文件夹复制过去了，为什么还是读不到？

多半是把旧的 .world 也一起复制了。它写着旧世界名，游戏因此认为这个目录属于别人， 转而新建了一个哈希目录。保留目标目录自己的 .world，只复制 .json。

两个不同名字的世界，却共用同一份路？

先确认「不同名字」是不是只改了存档文件夹。文件夹名的不同不改变世界名；两个世界名完全一样时， 共用是预期的（见场景四）。如果确实是不同名却共用，看看是不是还在用没有 .world 标记的 旧版本：升级后先打开你想保留数据的那个世界，它认领旧目录；另一个世界会得到哈希目录，再按需搬。

数据能合并吗？

不能自动合并。同一维度只有一个 <维度>.json，两张路网没有「取并集」的入口。 如果两边都有想保留的路，先各自备份，选一份作底，再把缺的路重画一遍。

目录里出现了 .part 或 .corrupt 文件

.part 是保存中途留下的半成品，正常退出后一般不会留着； .corrupt 是道路文件读不回来时被改名放到一边的原文件，可能还能手工救回一部分。 两者都先别删，备份整份目录再排查。

几条规矩

  • 先备份。复制整个 config/howtogo/；想把设置一起带走，再加 config/howtogo-client.toml。
  • 关游戏再动文件。路网会在停手后自动写盘、离开世界时再存一次， 开着游戏替换文件可能被旧数据盖回去。
  • 复制 .json，不复制 .world；不要整个文件夹覆盖。
  • 目录名和地址要一字不差。服务器地址的大小写、端口、写 IP 还是写域名，都算不同的世界。
  • 数据只在客户端。服务器上没有你的路，换电脑不会自动同步，也不会从服务器下回来。
  • 删模组 jar 不会删数据。反过来说，删掉 config/howtogo/ 才会； 误删先看回收站和之前的备份。
