更新日志

每个版本只写玩家看得见的变化，以及为什么这么改——「为什么不那样做」往往比功能本身更值得读。 版本号按语义化版本：第二位动是新增功能，第三位动是修 bug 或只改显示。

0.2.0 — 2026-10-03

新增

功能 说明
MTR 集成 读取 MTR 的车站与线路：列车 / 缆车算铁路，船算水路，其它类型（例如飞机）不猜； 站点取站台的中点；完全反射只读，MTR 没装或换版本都不影响本模组。 详见 MTR 集成。
MTR 轨道标记 MTR 的协议里没有「这条线路走哪段轨道」，所以问道对相邻站点对在 MTR 的轨道上规划一次， 把它实际走过的轨道标成只读的铁路 / 水路道路。每条线一个开关。
公共交通线路（L） 一屏三列建完一条线；线路有类型，接不上上一站的站点标红； 只读线路可以「复制为我的」。详见 公共交通线路。
地图显示面板 左上角可拖动、可卷起的面板，按等级 / 地点类型 / 线路逐个开关； 缩小地图时还会按等级自动取舍。详见 地图显示与缩放。
单行道（O） 双向 / 顺向单行 / 逆向单行三态，按整条街生效，地图上画箭头指出方向， 所有交通方式（含步行）都遵守。详见 画路、命名与地点。
地点类型 地点 / 资源点 / 商店 / 站点。类型影响显示与缩放取舍，不影响导航；只有「站点」必须建在道路上。
换乘站 同一处被两条及以上线路共用的站点画成橙色方块（尺寸与站点相同）， 只有屏幕上真的重叠时才融合，拉近看就分开。
「修路」 repair_road_joins：两条路交叉而过、或差一格没接上时， 规划前先把这种地方修好（只在不改变「桥还是桥」的前提下）。
MCPhone 兼容 手机里多一个「问道导航」应用，等于一个打开目的地选择界面的入口。

改进

  • 名字好看多了：字号跟着缩放走，缩小时按比例变小到仍然看得清的下限，放大时增长得很慢 （约 38 倍缩放才到最大字号）；线上名字顺着线的方向写、取行高一半让道路从字中间穿过； 地点名保持水平；名字宽度超过整条路时整条不画；缩小时名字自动贴近它标注的标记。
  • 步行接驳实际上没有上限了：没路的时候人本来就是直线走过去，只是按离开路面的速度计时。 一个 64 格的上限会让「明明就在眼前、但离路 65 格」的地方回答「没有路线」，那是唯一无法执行的答案。 驾车与公共交通仍是 64 格。
  • 地图面板不再被盖住：它是屏幕覆盖层，线路、标记、文字都压不到它上面，点击也不会被地图截走。
  • 平移地图不再拖影：屏幕上的一切都改用地图这一帧自己的变换来定位。

配置与数据文件

  • 新增配置：repair_road_joins、transit_wait_seconds、 mtr_transit、mtr_auto_route_marks。
  • 新增数据文件：<维度>-lines.json（公共交通线路）、 map_filter.json（显示开关与面板位置）。两个都是单独的文件， 出问题也碰不到你的路网。

0.1.0 — 2026-09-26

首个版本，把「画路」和「导航」接在了一起：

  • 画路：六个等级（高速 / 公路 / 小路 / 铁路 / 水路 / 冰道）、自动吸附、 Alt 自由放置、在路段中间落点会真正拆分路段并在交点建立节点、整条路共用一个名字、 地点标记、节点可拖动、撤销 / 重做 64 步。
  • 机械动力铁路自动识别：优先读 Create 的轨道网络（弯道是平滑曲线）， 读不到时回退为扫描轨道方块；铁路只读但可整条命名；Create 的车站成为可导航的目的地。
  • 导航：步行 / 驾车 / 公共交通三种方式；最快时间 ↔ 最短距离；避开等级； 优先大路；先预览再出发；按「交通方式 + 道路等级」估算时间；HUD 与语音播报；偏航重算； 不画横穿地图的直线，接驳太远就如实报「没有路线」。
  • 导航仪物品：右键选目的地，九格配方（四角铁锭、四边纸、中心指南针）。
