安装与前置

问道是纯客户端模组：装在你自己的客户端就够了，服务器上不装它也能正常玩， 它也不会要求服务器配合什么。换句话说，在任何服务器里，你都能独自使用它； 你画的路、标的地点只存在于你的客户端。0.2.2 起同时提供 Fabric 与 NeoForge 两种加载器的构建 （0.2.2 的 11 个 Fabric 包因为元数据写法一个都装不上，0.2.3 已经修好）。 0.2.3 起服务端也可以装：联机时服务端也装本模组（以及 MTR），才会把 MTR 正在模拟的 整张路网同步给你（只在 1.20.6 与 1.21.1 的节点上可用）；不装也照样能玩， 只是你没走到过的铁路问道就不知道。

版本要求

0.2.3 覆盖 Minecraft 1.20.1 到 1.21.11 以及 26.1 ~ 26.3， 共 21 个构建（Fabric 11 个、NeoForge 10 个；1.20.1 只有 Fabric）。 下载时挑与你游戏版本和加载器都对应的那一个：

✔ 表示有对应构建，— 表示这一版没有那个加载器的构建。 不支持 Forge：ForgeGradle 与当前的构建工具链冲突，Forge 的构建已从仓库移除。 构建文件名形如 howtogo-0.2.3+mc1.21.1-neoforge.jar， 里面带着 Minecraft 版本与加载器，按名字对号入座即可。 0.2.2 的包名里带着 pre1 后缀，0.2.3 的包名里没有它了。

0.2.3 一共 21 个构建：11 个 Fabric + 10 个 NeoForge，覆盖 Minecraft 1.20.1 ~ 1.21.11 与 26.1 ~ 26.3（1.20.1 只有 Fabric）。21 个构建全部通过编译与静态检查 （元数据、入口类、mixin、资源、语言键、依赖区间、class 版本、LICENSE）， 纯逻辑回归 1005 项全过。

其中 18 个节点用真实客户端跑过 9~10 项功能自检（路网、线路、规划、存档、 地点详情、导出导入、网页地图、界面主题）；Fabric 的 26.1 / 26.2 / 26.3 三个节点只验证到「客户端能启动、能进世界、路网读取正常」——当时开发工具链（Loom 与 Fabric API 的命名空间）让开发环境的客户端起不来，所以没跑完整自检。可选模组的完整组合 （Create、MTR、MTR Map Overlay、MCPhone、阡陌交通、Xaero 小地图与世界地图） 只在 1.21.1 NeoForge 上实测；1.20.1 Fabric 的专用服务器也启动到了 Done。遇到问题请附上 latest.log。

现在发布的是哪一版

版本 状态 说明
0.2.3 已发布 GitHub Release v0.2.3（2026-10-31），21 个构建。 本站的教程与功能说明描述的就是这一版。
0.2.2 上一版 GitHub Release v0.2.2（2026-10-18），包名带 pre1 后缀。 它的 11 个 Fabric 构建把 Minecraft 版本范围写成了 Fabric 不认的区间写法， 于是一个都装不上；0.2.3 已经全部改好，用 Fabric 的话直接换 0.2.3。

从 0.2.2 升到 0.2.3，先知道一件事：导航仪物品被移除了——物品、配方、 进度、创造模式标签页、语言与模型一起删了，本模组不再注册任何物品，打开本模组界面的 入口只剩 K 键。存档里已经拿到的导航仪会因为物品 ID howtogo:navigator 不存在而读不出来，升级日志里会报 unknown registry key——这不影响存档本身，K 主界面、 /howtogo terminal 与手机里的「问道导航」都还在。

另外，K 键在 Fabric 上 0.2.3 才真正注册并生效；0.2.2 的 Fabric 玩家按它没有反应， 这不是你的键位设置出了问题。

需要哪些模组

模组 必要性 说明
Xaero's World Map 必需 装与你的 Minecraft 版本对应的版本：1.20.6 与 1.21.6 的节点声明 [1.39.0,)（这两个版本只出过 1.39.x 那一代），其余节点声明 [1.40.0,)。所有道路、线路与路线都渲染在它上面； 缺少时模组会在日志里报错并停用渲染层。
XaeroLib 26.x 必需 26.x 起需要它，随 World Map 以嵌套 jar 一起分发，不用单独下载； 1.39.x 那一代把它合在 World Map 里、没有独立 jar，所以 1.20.6 / 1.21.6 的节点不单独要求它。
Fabric API Fabric 必需 用 Fabric 时需要 Fabric Loader（0.14.0 及以上）与 Fabric API； NeoForge 不需要它。
NeoForge NeoForge 必需 用 NeoForge 时需要与你的 Minecraft 版本对应的 NeoForge。
Xaero's Minimap 可选 装了以后，小地图上你插的路标点会出现在目的地列表里。0.2.3 起还能把整张路网、路线与 终点/起点标记直接画到它的小地图上（map_display_mode = xaero_minimap， 屏幕上只留一张精简卡片）；不过这次 21 个 jar 里只有 1.21.1-neoforge 真的编进了这一段，其它节点选它只会回退到自带 HUD。
Create（机械动力） 可选 自动识别铁轨与车站，见 机械动力铁路。
MTR（我的世界铁路） 可选 读取 MTR 的车站与线路（读取器要求 MTR 4.0.4 及以上）。 0.2.3 起，服务端也装本模组与 MTR 时，会把 MTR 正在模拟的整张路网 （每个维度的全部车站、线路与轨道）同步给客户端——只在 1.20.6 与 1.21.1 的节点上可用，见 MTR 集成。
阡陌交通（RoadWeaver） 可选 读取它自动生成的道路与结构，见 阡陌交通。
MCPhone 可选 在手机里多出一个「问道导航」应用，等于一个打开目的地选择界面的入口。

Java 也跟着节点走：按节点分别是 17 / 21 / 25，26.x 需要 Java 25。

所有可选模组都是通过方块注册名或反射读取的： 问道的构建脚本里没有任何一个的依赖。这让「没装」这件事变得无害——对应图层为空， 其它功能照常；也让它们换版本、改包名时，问道最多是读不到，而不是编译不过或直接崩。

安装步骤

  1. 选好 Minecraft 版本与加载器，装好 Fabric Loader + Fabric API 或对应版本的 NeoForge，确认能正常进入游戏。
  2. 把与你 Minecraft 版本对应的 Xaero's World Map 放进 mods/； 26.x 不用另外找 XaeroLib，它随世界地图分发。
  3. 把对应构建放进同一个 mods/，例如 1.21.1 + NeoForge 就用 howtogo-0.2.3+mc1.21.1-neoforge.jar；Fabric 则用同一版本号里 -fabric 的那一个。
  4. 启动游戏。日志里出现 [HowToGo] constructed 就说明模组已经加载。

想要识别机械动力铁路、MTR 线路或阡陌交通的路，再把对应模组也放进 mods/； 它们是随时可以加减的——加进来图层立刻有内容，拿掉图层立刻为空，你的路网不会因此受损。

进游戏后先确认这三件事

  1. 打开世界地图，左上角应该出现「地图显示」面板（可以拖动、可以卷起）。 看不到它，多半是 Xaero 的世界地图没装或版本不对。
  2. 在世界地图上按 R，屏幕左下角出现绘制状态与路网统计、右下角出现快捷键列表， 说明编辑模式已经打开。
  3. 按 K 打开主界面（0.2.2 新增）：0.2.3 起导航仪物品已经移除，K 是打开本模组界面的唯一入口，选择目的地、切换出行方式、开始或结束导航 都在里面；Fabric 上也是 0.2.3 才真正注册了这个键位。也可以在世界地图上按 Ctrl + 左键直接点目的地。

地图显示面板的默认位置是左上角往里一点。如果那里正好被别的模组（例如机械动力自己的界面） 占着，直接拖它的标题行换个位置即可，位置会被记住。

数据放在哪

所有数据都在客户端的 config/howtogo/ 下，按世界分开： 单人存档按世界名（sp_<世界名>），多人服务器按服务器地址（mp_<地址>）。 0.2.2 起目录名里的中文会转成拼音（sp_新世界 → sp_xin_shi_jie），ASCII 名字原样保留，其余非法字符换成下划线。 第一次用新版打开旧世界时，整个目录会自动改名，不需要你做任何事； 风险在降级——用 0.2.2 存过档再退回 0.2.1，那个世界的路网会是空的。 改名、换地址或换电脑时怎么搬，见 迁移地图数据。 坐标只在一个维度里有意义，所以文件名里还带着维度； 维度文件名不经过拼音（minecraft_overworld.json 就是它）， 所以升级不会让已有的路网「消失」。

文件 内容
<维度>.json 道路网络：节点、路段（含可选的平滑折线 curve）、名称、地点与地点类型。
<维度>-lines.json 公共交通线路：线路名、类型、按顺序的站点。
<维度>-rail-names.json 自动识别铁路的名称（单独一个文件，因为铁路图层每秒重建）。
place_details.json 每个地点的描述、标签与收藏（0.2.3 起；按存档存、不按维度，3 秒防抖 + 原子写）。
route_preferences.json 上次选择的交通方式与路线偏好。
map_filter.json 地图显示面板的开关、卷起状态与位置（与存档无关）。
mtr_overlay_toggles.json 装了 MTR Map Overlay 时，记住它在世界地图上的「线路 / 轨道」两个开关（0.2.2 起）。
exports/、backups/ 地图存档压缩包：导出的包与导入前的备份（0.2.2 起，见 迁移地图数据）。 0.2.3 起包里还带着 place_details.json，导入回来地点详情一起恢复。
../howtogo-client.toml 客户端配置，见 配置与数据文件。

想备份路网，复制整个 config/howtogo/ 目录即可，也可以在一个世界里用 /howtogo data 把当前世界打包成 .zip； 想在不同电脑之间搬家，两种方式都行（压缩包同样能导入回来）。 反过来，删掉模组的 jar 不会删掉这些文件——路网是你的数据，不是模组的缓存。 单个世界的迁移（改世界名、换服务器地址、复制存档）见 迁移地图数据。

因为它是纯客户端的，别的玩家看不到你画的路，也看不到你的导航。 这是设计选择（不需要服务器配合、也不用担心服务器权限），不是缺陷。
